# 调研：配置快照与复用计划（P-148）

> **Feature**：P-148。兑现 P-147 U-1 的第一档：让导出的 pipeline skill 携带**脱敏配置**，从而可以生成可执行的重跑命令。
> **性质**：T1 实施批；单分支、单 PR。
> **结论先行**：① 采用「配置指针 + 脱敏快照」（用户裁决 B 档）；② manifest 升 v2，v1 保持可读；③ 脱敏规则保守：凭据值、绝对路径、`~` 路径一律替换，`*_env` 保留键名；④ 只生成计划，不自动执行。

## 1. 问题

P-147 能证明「记录的成功路径仍完好」，但不能回答「怎么重跑」。缺的是配置：manifest 刻意不含 prompt（P-145 D-7），但**配置**可以脱敏后携带。

| 方案 | 安全性 | 可重跑性 |
|---|---|---|
| 不存配置（P-147 现状） | 最高 | 无 |
| 存原始配置 | 低：含 API key、SSH 路径 | 完整 |
| **存脱敏快照（采用）** | 中：凭据与路径被替换 | 需人工补齐被脱敏项 |

## 2. 脱敏规则

| 规则 | 处理 |
|---|---|
| 键名匹配 `api_key` / `token` / `secret` / `password` / `credential` / `private_key` 且值非空 | 值 → `***REDACTED***` |
| 键名以 `_env` 结尾 | **保留**：存的是环境变量名，不是密钥 |
| 值以 `/`、盘符、`~/`、`\\` 开头 | 值 → `<REDACTED_PATH>` |
| 其他 | 原样 |

被替换的键路径写入 `config.redacted_keys`，供人工补齐与审计。

## 3. 风险

| 风险 | 处理 |
|---|---|
| 脱敏漏判（键名不规范） | 规则覆盖常见凭据命名；已知边界写入文档，不宣称完备 |
| 路径替换后无法直接重跑 | `plan` 明确标 `needs_manual_fill` 并列出键路径 |
| 快照被篡改 | 快照带 sha256，加载时比对，不匹配拒绝 |
| v1 技能不兼容 | v1 继续可加载；`plan` 对 v1 返回 exit 2 并提示重新导出 |

## 4. Review 记录（Step 4）

- 对照 P-145 D-7：本批不存 prompt，只存配置，安全边界未被推翻。
- 对照 P-147：verify 已校验产物/动作/链；本批只扩展 manifest 与加载校验，不重复。
- 修正一处：初稿只认 `/` 与盘符，漏掉 `~/.ssh` 与 UNC 路径，测试暴露后扩展正则。

## 5. 范围

- 做：脱敏器、manifest v2、加载校验、`pipeline-skill plan`。
- 不做：自动执行、prompt 存储、配置合并、多 run 快照、密钥托管。

## 6. 诚实边界

- 脱敏是**命名启发式**，不保证覆盖所有自定义密钥字段。
- 被脱敏的路径需要人工补齐，因此 `plan` 是「计划」而非「一键重跑」。
- 未验证重跑结果与原始 run 等价；等价性需要另一套对照实验。
