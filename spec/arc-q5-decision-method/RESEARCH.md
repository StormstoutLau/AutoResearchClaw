## 2. 复现：加权总分为什么失效

### 2.1 数值不可复算

P-022 §3.4 给出 A=4.2 / B=3.6。按「高=3/中=2/低=1」复算（P-023 已做、本批复验）：

| 方案 | 加权和 | 归一化 | P-022 原文 |
|---|---|---|---|
| A 纯文件 | 74 | 4.11 | 4.2 |
| B SQLite | 68 | 3.78 | 3.6 |
| 权重合计 | 18（高×3 + 中×4 + 低×1） | — | 未给出 |

原文未公开权重映射（高/中/低 → 何数值），因此 4.2/3.6 **不可复算**。

### 2.2 反转条件可精确写出

记 8 个维度的「A−B」差值为

```
d = (+2, −2, −1, 0, −1, +2, +3, +1)
     d1   d2   d3  d4  d5   d6   d7   d8
    (一致性)(崩溃)(fsync)(租约)(outbox)(运维)(迁移)(并发)
```

则 **A ⪰ B 当且仅当**

```
2·w1 − 2·w2 − w3 − w5 + 2·w6 + 3·w7 + w8 ≥ 0
```

- 默认权重（高3/中2/低1）：`2·3 − 2·3 − 3 − 2 + 2·2 + 3·2 + 1 = +6` → A 胜。
- 把 B 的三项强项（崩溃/fsync/outbox）提到「高」、把 A 的四项（一致性/运维/迁移/并发）降到「低」：
  `2·1 − 2·3 − 3 − 3 + 2·1 + 3·1 + 1 = −4` → **B 胜**。

即：**排序由权重向量决定，而非由事实决定**。这就是加权总分不能作为裁定依据的严格理由。

## 3. 失效原因（五点）

| # | 原因 | 说明 |
|---|---|---|
| E-1 | 权重口径未公开 | 不可复算 = 不可审计 |
| E-2 | 序数当区间数用 | 「5 分」与「3 分」的差 2 无度量意义，加权求和隐含等距假设 |
| E-3 | 维度相关导致双重计数 | d2（崩溃恢复）与 d3（fsync 可控性）高度相关，B 的同一优点被计两次 |
| E-4 | 归一化与表示敏感 | 多准则决策中的经典问题：排序可随归一化/加项变化而反转 |
| E-5 | 无敏感性分析 | 单点总分掩盖了「换一组合理权重就翻盘」 |

## 4. 外部锚点

| # | 锚点 | 可复用结论 | 等级 |
|---|---|---|---|
| X-1 | SEI ATAM（Bass *Software Architecture in Practice* ch.11；Carleton 讲稿） | 架构权衡的分析单位是**敏感点/权衡点**（sensitivity / tradeoff point），不是加权总分；ATAM 明确「目的不是给出精确分析」 | T1 教材 / T2 讲稿 |

## 5. 替代决策程序（P-025 方法）

**五步，全程不用加权总分**：

| 步 | 名称 | 规则 |
|---|---|---|
| **S-1** | 硬约束筛选（conjunctive） | 列出必须满足的门槛；任一不满足即**淘汰**（非补偿，X-4） |
| **S-2** | 支配检验（Pareto） | 若某方案在所有维度不劣且至少一维更优 → 直接胜出；若互不支配 → 进入 S-3 |
| **S-3** | 定位敏感点（ATAM sensitivity point，X-1） | 把「使排序翻转的维度子集」显式写出；决策被压缩为**一个规范性问题** |
| **S-4** | 用可逆性裁定（X-6） | 当证据不足以判定孰优时，选**回退成本更低**的方案；并说明回退路径的具体形态 |
| **S-5** | 登记翻转条件（kill criteria） | 明确「什么事实出现时必须重审」，替代「权重」作为变更触发器 |

**禁止**：再用 4.2/3.6 一类总分作为裁定依据；若要保留评分，必须公开权重映射并附敏感性区间（本仓暂不采用）。

## 6. Q5 按新程序重推

### 6.1 S-1 硬约束

| # | 约束 | A | B | 结论 |
|---|---|---|---|---|
| C-1 | 可由事件日志重建 checkpoint（A1-5） | ✓ | ✓ | 均过 |
| C-2 | 不引入 stdlib 之外的运行时依赖 | ✓（纯文件） | ✓（`sqlite3` 为 stdlib） | 均过 |
| C-3 | 可表达单 run 单写者（A1-4） | ✓ | ✓（WAL 单 writer） | 均过 |
| C-4 | 不破坏 checkpoint 权威性（I-1） | ✓ | ✓（事件仍是投影） | 均过 |

→ **无淘汰**，进入 S-2。

### 6.2 S-2 支配检验

- A 优：一致性 d1(+2)、运维 d6(+2)、迁移 d7(+3)、并发 d8(+1)
- B 优：崩溃恢复 d2(−2)、fsync 可控 d3(−1)、outbox 原子 d5(−1)
- 互不支配 → S-3。

### 6.3 S-3 敏感点

由 §2.2 的不等式，**全部翻转都由 d2/d3/d5 相对 d1/d6/d7/d8 的加权消长决定**。扣除 E-3 的相关性重复（d2 与 d3 合并为「崩溃期正确性」一项，抵消权重），决策实际只剩一个问题：

> **「事件层的崩溃期正确性」是否应当优先于「与既有 file-as-state 架构的一致性 + 更低迁移成本」？**

这是一个**规范性**问题，不是可以靠打分回避的技术问题。

### 6.4 S-4 可逆性裁定

| 迁移方向 | 成本形态 |
|---|---|
| A → B | 替换 `DurableBackend` 实现 + 一次导入；**不改**事件语义与上层 API（前提：§8 的后端中立信封） |
| B → A | 需要 schema 迁移 + `events.db` 历史数据处理 + 导出 |

两者都不是 one-way door，但 **A→B 的回退成本显著更低**。按 X-6，在「事实不足以判定孰优」时选可逆成本更低者。

**裁决 = 倾向 A（file + supervisor）；B 为可辩护备选。**

与 P-023 的结论一致，但**理由从「总分 4.2 > 3.6」改为「约束无淘汰 + 互不支配 + 可逆性更低」**——后者不依赖任何权重。

### 6.5 S-5 翻转条件（kill criteria）

沿用 P-022 §6.1，并补一条测量口径：

| # | 触发 | 阈值 | 动作 |
|---|---|---|---|
| K-1 | 单 run 事件数 | > 10⁵ | 重审（B 的索引/查询优势显现） |
| K-2 | 同一 run 多 worker 并发写 | 出现需求 | 重审（需事务/行锁） |
| K-3 | 跨 run 事件查询/检索 | 出现需求 | 重审 |
| K-4 | fsync 摊销占运行时长 | > 5%（实测，非估计） | 重审 |
| K-5 | 事件层出现数据丢失事故 | 1 次 | 立即重审（B 的成熟恢复机制成为强证据） |

## 7. Q9 按新程序重推（约束即结论）

| # | 硬约束 | A 热30/归档365/摘要永久 | B 永久全量 | C 7 天 |
|---|---|---|---|---|
| C-1 | 支持单 run 体积上限（A1-6） | ✓ | **✗ 无界增长** | ✓ |
| C-2 | 覆盖「一次 run 从失败到人工复核」周期（≥30 天） | ✓ | ✓ | **✗ 仅 7 天** |
| C-3 | 满足数据最小化（GDPR Art.5(1)(e)） | ✓ | **✗ 永久保留全量** | ✓ |
| C-4 | 归档后仍可验证链完整性 | ✓（摘要存首尾 digest） | ✓ | ✗（无归档） |

- **B 被 C-1/C-3 淘汰；C 被 C-2/C-4 淘汰 → A 唯一存活，S-2 之后无需进行。**

**意义**：Q9 的结论**不需要任何权重**，因此 P-023 的「Q9 稳健」现在有了更强的形式——不是「权重扰动下仍稳」，而是「不依赖权重」。

## 8. 对 G1 实施批的约束

1. **禁止**在 G1 的设计文档中再用加权总分裁定后端或保留策略；用 §5 五步法，并落 ADR 形态（Context / Decision / Consequences / Status，X-7）。
2. `EventEnvelope` 必须**后端中立**：不出现文件路径、行号、fsync 等存储细节，否则 A→B 的可逆性前提（§6.4）失效。
3. `DurableBackend` 接口需在 G1 第一版就定义（即使只实现 A），否则 K-1..K-4 触发时退化为重写。
4. K-1..K-5 写入 G1 的 CHECKLIST，作为「允许改变 Q5 结论」的唯一合法入口。
5. P-022 §3.4 的 4.2/3.6 **不再被引用**；如需引用，指向本文件 §6。

## 9. 未决项

- **U-1 敏感点合并是否成立**：判据 = d2（崩溃恢复）与 d3（fsync 可控性）是否真的高度相关；触发 = G1 设计评审；倾向 = 合并；E2。
- **U-2 K-4 的测量方式**：判据 = fsync 摊销如何量化（事件写入耗时 / run 总时长）；触发 = 事件层落地后首轮压测；倾向 = 埋点计时；E2。
- **U-3 是否需要为 Q9 单独 ADR**：判据 = Q9 是否仍有争议；触发 = 裁决确认时；倾向 = Q5/Q9 合一 ADR；E3。
