| ID | 套件 | 覆盖 | 生效起点 |
|---|---|---|---|

**`N/A` 语义**：某成员所属阶段尚未完成 → 记 `N/A`，不计红；所属阶段完成后自动转为必绿。这样 G0a/G-1 出口不再被未来阶段的能力卡死，同时 G-1 完成当刻 H-1..H-4 开始受回归保护。

## 3. 影响面

- 验收计数：不变（C 套件不计入 106 条）。
- 阶段划分与依赖图：不变。
- 门禁脚本：不改；`dc_validator` / `step_enforce` / `console_gen` / `rework_graph_check` 行为不变。
- 审查报告（P-002）：不改写，仍绑定 v0.1 / `7d0e70a`；新旧版本关系由 D-6 的修订块声明。

## 4. 回滚

单提交内完成，回滚 = `git revert`。由于只改文档，回滚后不影响任何运行时代码；但需同步回滚 `docs/PROGRESS.md` 的 P-003 行与 session（否则 `step_enforce` 在 batch 模式下找不到对应批次）。

## 5. 边界与局限

- 本批不追求 C 套件对 106 条的穷举，只保证「G-1 有回归闸门」与「未落地成员不被误判红」。
- `N/A` 是人工判据，尚无脚本强制；覆盖脚本只能检查"成员是否出现在某套件"，不能判断生效时点。
- 平台仍为 Windows，P2-08（`kill -9`/退出码 137）未在本批处理。
