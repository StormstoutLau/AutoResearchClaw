# 设计：审查的规则映射、取证矩阵与问题分级

## 1. 规则映射

| SPEC_PROCESS 规则 | 本审查的落地方式 |
|---|---|
| RULE-1 时序独立 | 审查在 15 份文档完稿后的独立 pass 执行，非与正文同一次写入 |
| RULE-2 统计溯源 | 106 条验收逐阶段复算；无法复现的 A2-3 单独列为 P2-07 |
| RULE-3 环境确定性 | 记录本机 Python 3.13.5 / Windows，并标出 Linux-only 验收项 |
| RULE-4 单 Agent | 报告首页声明单视角，结论不一概标绿 |
| RULE-5 异质基座 | 明确未满足，报告不构成最终合规结论 |
| RULE-6 证据绑定 | 每条 P1/P2 绑定 E1–E4；E5 推测不入结论 |

## 2. 取证矩阵设计

| 等级 | 用途 | 本次覆盖 |
|---|---|---|
| E1 | `rg` / `git` / `python -c` 可重放命令 | 8 条代码事实、106 条计数、依赖闭合 |
| E2 | 直读源 JSON 的运行时脚本 | Paper 2,487、Textbook 1,824/20,235 |
| E3 | 静态读码行号（绑定 `7d0e70a`） | executor/config/runner/stage_impls 锚点 |
| E4 | WebSearch/WebFetch 与人工一致性扫描 | 26 条外部引用、§1–§11 交叉引用 |
| E5 | 推测 | 仅出现在「未覆盖项」，不入结论 |

## 3. 问题分级

- **P1 阻断**：使后续阶段验收恒假或无法判定，必须在对应阶段开工前修复。
- **P2 应修**：改变设计输入或降低验收强度，但不改变路线方向。
- **P3 提示**：表述、计数、编号漂移。

## 4. 边界声明

- **职责外**：不重新调研 ClawsGO 逆向事实，不验证开源项目的内部实现质量。
- **能力边界**：未读论文全文，因此只能判定「引用与标题是否匹配」，不能判定「论文结论是否支持文档的因果主张」。

## 5. 修复策略

只输出问题清单，不改被审文档（ADD 单向权限）；修复由文档所有者执行，本审查不自动改写实现。
