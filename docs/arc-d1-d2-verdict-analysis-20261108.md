## 1. D-1 分析

### 1.1 七维对比

| 维度 | A. 移入 C-9 | B. 拆 C-9a/b | C. 成员级标注 |
|---|---|---|---|
| **成本** | 低：2 行编辑，无引用变更 | 中：1 行拆 2 + §5 规则行引用改 | 极低：1 行加注 |
| **收益** | G-1 出口强制 H-5 | 同 A | 同 A（读法明确） |
| **兼容** | 与 §5 既有 N/A 规则同构：成员生效点 = 交付阶段 | 同 A | 兼容但语义依赖人工读箭头 |
| **维护** | 未来 G-1 新护栏（GAP-2/3 的 agent trace）天然归 C-9 | 新增成员需在 a/b 间二选一 | 每次新增都要加箭头——当前歧义正源于箭头漏标 |
| **升级** | C-9 单套件承载全部 G-1 可信成员，长期稳定 | 双套件边界随新护栏漂移 | 同 A 但更脆 |
| **短期** | 立即消歧 | 立即消歧 | 立即消歧，机制未变 |
| **长期（可机判）** | 生效点可由"交付阶段"机械推导，可写入差集脚本扩展 | 同 A | 箭头不可机判：V5 差集脚本只认 ID/区间，箭头是肉眼元数据 |

### 1.2 外部证据与论证

| 锚点 | 对 D-1 的支撑 |
|---|---|
| **E-1** Fagan/NIST：缺陷在早期阶段修复比后期便宜 10–100 倍（NIST/SAMATE 论文引 Fagan 1976；NIST 2002 报告的 1-10-100 量级） | 伪造执行护栏的**强制点应等于其交付点 G-1**；延至 G3 意味着 G-1→G3 之间产出的实验结果不受 H-5 保护，正是缺陷成本曲线的最贵区间 |
| **E-8**（内部既有锚）MLR-Bench（arXiv 2505.19955）："合成/占位数据冒充真实执行"是已被证实的失败模式 | H-5 不是防御性设计，是对已证实风险的直接对冲，强化"必须早强制" |
| **E-3** GitHub protected branches / required status checks：`disable the merge button until they pass`——门禁在**变更落地的边界**阻塞，Azure DevOps 分支策略同构 | 工程惯例：门禁属交付边界，不属下游阶段 |
| **E-2** NIST SP 800-218 SSDF：PW.8 "Test executable code" 属构建期实践，框架按产物产出阶段组织 | 同向：护栏归属产出该产物的阶段 |
| **E-6** SonarQube Quality Gate：二值 pass/fail，"是否可发布"只有一个答案 | 门禁语义应二值且边界清晰，不应靠行内箭头推断"何时开始算数" |

### 1.3 方案取舍

- **C 的本质缺陷**：把"何时生效"继续放在不可机判的箭头里——复核报告 F-2 已确认箭头漏标正是本次歧义的直接成因。选 C 等于把已发现的缺陷模式固化。
- **B 的拆分收益**（数据正确性 vs 执行真实性主题分离）不抵其成本（两行 + 引用改动 + 未来成员归位需二选一）；A 用名称泛化（"可信执行（G-1）"）即可覆盖两主题。
- A 与 §5 既有 N/A 规则**同构**：成员生效点恒等于交付阶段，成为可推导不变量，而非逐行声明。

### 1.4 建议

> **D-1 采纳方案 A**：H-5 移入 C-9（覆盖 H-1..H-5，名称"可信执行（G-1）"，生效起点 G-1）；C-7 收缩为 FC-1..3 + FA-1..3（名称"失败护栏（循环与漂移）"，生效起点 G7）；**顺带删除 §5 全部成员级箭头**（生效点一律由交付阶段推导）。

## 2. D-2 分析

### 2.1 七维对比

| 维度 | A. 生效起点标注 | B. 移入 G3 | C. 纯函数化改写 |
|---|---|---|---|
| **成本** | 文档小改，但需**发明新机制**：阶段出口 N/A 语义 + 修改 L572 硬出口 | 中：3 行迁移重编号 + §3 计数表改 + §5 声明区间破碎 | 中：3 断言改写 + G2 交付物 +1 + A3-1 扩写 |
| **收益** | G2 出口"全绿"稀释为"全绿或 N/A" | G2 出口可判 | G2 出口可判，且三条全部为内核级断言 |
| **兼容** | 与"本阶段验收项全绿"硬出口**直接冲突** | §3 阶段总表与总数行必须改；A2 区间引用断 | **106 计数、§3、§5 全部不动** |
| **维护** | **N/A 蠕变先例**：任何阶段都可效仿把难判据推迟到"生效起点" | 稳定 | 稳定；复用 A2-1 的 schema+fixture 管道 |
| **升级** | — | G3 +3 条 | G3 接线后 A3-1 端到端直接覆盖；**顺带解决复核发现的 Stage 22 接线无归属** |
| **短期** | 最快 | 快 | 慢：需先设计谓词与 fixture |
| **长期** | 差（门禁侵蚀） | 良 | 优：发布判定成为 ClaimRecord 契约的一部分 |

### 2.2 外部证据与论证

| 锚点 | 对 D-2 的支撑 |
|---|---|
| **E-5** ISO/IEC 12207：**verification** 验"活动输出满足前序活动施加的条件"；**validation** 验"系统达成预期用途、目标"（IEEE 24765 收录的 ISO 12207 定义） | A2-4/5/6 的**判定逻辑部分属 G2 内核的 verification**（ClaimRecord 语义的派生谓词），端到端管线行为属 G3 的 validation。判据应与所在阶段的 V&V 层级匹配——这正是"放错位置"的根因 |
| **E-4** Test Pyramid（Fowler）：以单元层为主（约 70%），端到端少而脆、贵、慢，非确定性风险高 | 判定逻辑下沉为纯函数（单元层），接线验证留给 A3-1（集成层一条）——与金字塔分层一致 |
| **E-6** SonarQube Quality Gate 二值 pass/fail | 阶段出口是质量门禁，不应引入"N/A 也算过"的第三态 |
| **E-7** Atlassian/Scrum：验收判据必须 **Testable**；DoD 是增量的**单一透明完成状态** | "标注生效起点"实质是给增量完成状态开洞——判据写不出可测试形态，说明它不属于该阶段（应迁移），而不是该阶段可以暂欠 |
| **E-9**（内部）A2-2 已确立变异测试精神（判据必须能红）；A2-1 已有 16-fixture 管道 | 方案 C 的谓词 + fixture 是既有模式的直接复用，非新发明 |

### 2.3 方案取舍

- **A 被否决的核心理由**：为 3 条判据引入全局"阶段出口 N/A"机制，是**门禁侵蚀**——P-003 刚为 C 套件引入 N/A（跨阶段聚合语义下合理），阶段出口是主质量栏，语义不同。SonarQube/DoD 证据均指向"出口二值"。
- **B 的隐藏成本被低估**：不只是搬 3 行——§3 阶段总表计数（G2 7→4、G3 17→20）、总数行、§5 声明"A2-2..A2-7"区间破碎、A2-x 编号对 R-03 的溯源全部受牵连。
- **C 的额外收益**：Stage 22（EXPORT_PUBLISH）接线无归属是复核新发现的缺口，C 通过"A3-1 扩写 + G3 交付物补 Stage 22"顺带闭环；B/A 均不解决。

### 2.4 方案 C 的断言改写预览（供裁决参考）

| 现 ID | 改写后断言（内核级） | 负向用例（保留精神） |
|---|---|---|
| A2-4 | 谓词 `can_enter_deliverables(claim)`：`status ∈ {FALSIFIED, FAILED}` 一律返回 false；纯函数 + 1 正 1 反 fixture | 谓词对 FALSIFIED 返回 true 即失败 |
| A2-5 | 谓词 `requires_annotation(claim)`：`status = NUMERICALLY_VERIFIED` 必须携带注记；G3 渲染侧仅消费该谓词 | 缺注记仍可渲染即失败 |
| A2-6 | 谓词 `downgrade_missing_citation(claim)`：A/B 类缺引文 → 迁入 assumptions、status 降 speculation（不阻断），推导为纯函数 | 一律 fail 即违背原语义 |
| A3-1（扩写） | 端到端：ClaimRecord → 证据 → 段落 → Stage 20 拒绝 → Stage 23 核验 → **Stage 22 导出侧与谓词一致** | 任一处与谓词不一致即失败 |

## 5. 结论

1. **D-1 → 方案 A**（H-5 移入 C-9 + 删箭头）：成本与 C 几乎相同，但把生效点从"肉眼元数据"变为"可推导不变量"，与 §5 N/A 规则同构；C 是把歧义源头固化为制度，否决。
2. **D-2 → 方案 C**（纯函数化改写）：106 计数与全部既有区间引用零扰动；把三条判据还原为它们本来的 ClaimRecord 语义；顺带闭环 Stage 22 无归属。B 为低成本备选；A 因"阶段出口 N/A"的门禁侵蚀先例否决。
3. 两条建议的共同原则：**门禁在交付边界二值生效，判据与所在阶段的 V&V 层级匹配**（E-3/E-5/E-6）。
